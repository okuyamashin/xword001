# xword001 設計ドキュメント

多言語対応のクロスワードパズルを自動生成し、1日1問公開する静的サイト。
最初は日本語版を作る。

- ステータス: たたき台（相談しながら更新する）
- 最終更新: 2026-10-11

---

## 1. 目的と方針

| 項目 | 方針 |
|---|---|
| 形態 | 静的サイト（サーバー処理なし）。1日1回ビルドして公開 |
| 言語 | まず日本語。後から英語などを追加できる構造にしておく |
| 答えの扱い | HTML 内の JavaScript にヒント・答えをそのまま埋め込んでよい（隠さない） |
| 生成 | 盤面の組み立てもヒント作成も自動化する |
| 遊び方 | ヒントを選ぶ → 文字を入力 → マスが埋まる。諦めたら答えを見られる |

答えを隠さないので、暗号化やサーバー側での判定は要らない。そのぶん仕組みを単純にできる。

---

## 2. 全体構成

```
[単語リスト]          [テーマ設定]
      │                  │
      ▼                  ▼
┌──────────────────────────────┐
│ 1. 盤面生成（グリッドに単語を配置）  │
└──────────────────────────────┘
      │  配置済み単語の一覧
      ▼
┌──────────────────────────────┐
│ 2. ヒント生成（単語ごとにカギを作る）│
└──────────────────────────────┘
      │  puzzle.json
      ▼
┌──────────────────────────────┐
│ 3. 検証（品質チェック）             │
└──────────────────────────────┘
      │
      ▼
┌──────────────────────────────┐
│ 4. HTML 出力（テンプレート + データ）│
└──────────────────────────────┘
      │
      ▼
 GitHub Actions（毎日 cron）→ GitHub Pages で公開
```

- 生成スクリプトは Node.js（または Python）で書き、GitHub Actions で毎日実行する。
- 出力は `site/YYYY-MM-DD.html` と `site/index.html`（当日分）。過去問も一覧で残す。

## 3. UI 仕様（日本語版）

### 3.1 画面構成

```
┌─────────────────────────────┐
│  2026年10月11日のクロスワード  [テーマ: 秋の味覚] │
├───────────────┬─────────────┤
│               │ タテのカギ     │
│   盤面グリッド   │  1. 秋の…    │
│  （選択中の単語は │  2. …        │
│   ハイライト）    │ ヨコのカギ     │
│               │  1. …        │
├───────────────┴─────────────┤
│ [選択中] タテ1: 秋に旬を迎える… (4文字)│
│ [ 入力欄           ] [入れる]        │
│ [この答えを見る] [全部の答えを見る] [リセット]│
└─────────────────────────────┘
```

### 3.2 操作の流れ

1. カギ一覧の項目、または盤面のマスをタップすると、その単語を選ぶ。
   盤面の該当マスとカギがハイライトされる。
2. 入力欄に答えを入れて確定すると、マスが埋まる。
3. 交差するマスは、後から入れた文字で上書きする（上書きの前に確認は出さない）。
4. 全部のマスが正しく埋まったら「完成！」を表示する。
5. 諦めたときのボタンは2つ:
   - **この答えを見る**: 選択中の単語だけを表示する
   - **全部の答えを見る**: 盤面全体を表示する

### 3.3 日本語入力の扱い（重要）

マスに直接1文字ずつ打つ方式は、スマホの IME（かな漢字変換）と相性が悪い。
そこで「単語ごとに入力欄へ打って確定する」方式を基本にする。

- 入力されたひらがなはカタカナに変換して比較する（どちらで打ってもよい）。
- 小さい文字は大きい文字として扱う（`ャ→ヤ`、`ッ→ツ`、`ァ→ア`）。
- 「ヴ」は使わない。入力された「ヴ」はバ行に置き換える（8.1 の文字ルール）。
  日本のクロスワードで一般的なルール。
- 濁点・半濁点は区別する（`ガ` と `カ` は別の文字）。
- 長音「ー」は1文字として扱う。
- 文字数が足りない・多すぎるときは、入るぶんだけ入れて警告を出す。
- 正誤は入れた時点では出さない（任意で「答え合わせ」ボタンを付ける）。

### 3.4 但し書き（ルールの表示）

パズルの画面に、答えの書き方のルールを必ず表示する。2段に分ける。

| 種類 | 置き場所 | 例 |
|---|---|---|
| 全体のルール（言語ごと） | ロケール設定（`generator/locales/ja`） | 小さい文字は大きい文字で入れる／「ヴ」は使わずバ行で表す／濁点・半濁点は別の文字 |
| テーマのルール | テーマファイルの `rules` | 国名は略称（「アメリカ」「イギリス」）。正式名称ではない |

テーマのルールは、テーマファイルからクロスワードのファイルへ写し、HTML に表示する。
複数のテーマを組み合わせた日は、使ったテーマのルールをすべて表示する。

### 3.5 その他

- スマホ優先のレイアウト（盤面は画面幅に合わせて縮める）。
- 途中経過は `localStorage` に日付キーで保存し、再読み込みしても消えないようにする。
- 外部ライブラリなしで、1つの HTML ファイルで動くようにする。

## 4. 盤面の組み方（相談事項）

### 4.1 方式の候補

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. 日本式（黒マス型）** | 正方形の盤面を白マスと黒マスで埋める。白マスはすべて何かの単語に属する | 新聞・雑誌でおなじみ。密度が高く、解きごたえがある | 単語が大量に必要で、組むのが難しい |
| **B. 自由配置型（スケルトン）** | 単語どうしを交差させて自由に並べる。空白部分が残る | 組みやすい。テーマの単語だけで作れる | 交差が少ないと簡単になりすぎる |
| **C. 二重マス付き（A or B の拡張）** | 特定のマスの文字を並べ替えると「キーワード」になる | 最後にもう一段の楽しみがある。日本の懸賞パズルの定番 | キーワードの文字が盤面に含まれるよう調整が要る |

### 4.2 日本式（A）のルール

一般的な日本のクロスワードのルール:

- 黒マスはタテ・ヨコに連続しない（斜めは可）。
- 盤面の四隅は黒マスにしない。
- 黒マスで白マスが分断されない（すべての白マスがつながっている）。
- 2文字以上の並びはすべて単語にする（意味のない並びを作らない）。

### 4.3 生成アルゴリズム案

**A（日本式）の場合**

1. 盤面サイズを決める（初めは 7×7〜9×9）。
2. 上のルールを満たす黒マスの配置を作る（ランダム生成して条件で選別する）。
3. 単語の入る枠（スロット）を洗い出す。
4. 制約充足（バックトラック）で単語を埋める:
   - 候補が最も少ないスロットから埋める（MRV ヒューリスティック）。
   - 交差文字が決まったら、他のスロットの候補を絞り込む（前方検査）。
   - 失敗したら戻ってやり直す。一定回数で失敗したら黒マスの配置からやり直す。
5. テーマの単語を優先して入れる（スコアを高くする）。

**B（自由配置）の場合**

1. テーマの単語を長い順に並べる。
2. 1語目を中央に置き、残りを「既存の文字と交差できる位置」に置いていく。
3. 交差数が多い配置を優先する。何通りか試して最も密なものを採用する。

**提案**: まず B で動くものを作り、UI とヒント生成を固める。
その後 A に進む。A のほうが辞書（大量の単語）を必要とするため。

### 4.4 単語リスト

| 候補 | 内容 | 注意点 |
|---|---|---|
| JMdict（EDRDG） | 日英辞書。読みが付いている | CC BY-SA。クレジット表記が要る |
| Wikipedia の記事タイトル | 固有名詞・時事に強い | 読みの取得が別途必要 |
| 自作リスト | テーマごとに手で作る | 量が限られる |
| LLM で生成 | テーマを渡して候補を出させる | 読みや実在性の検証が要る |

日本語のパズルでは「読み（カタカナ）」がマスに入る文字になる。
単語ごとに `表記`・`読み`・`品詞`・`難易度`・`タグ（テーマ）` を持たせる。

## 5. ヒントの作り方（相談事項）

### 5.1 方式の候補

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **辞書の定義を流用** | 辞書の語義文をヒントにする | 正確 | 硬くて面白くない。答えがそのまま書かれていることがある |
| **LLM で生成** | 単語とテーマを渡してヒント文を作らせる | 自然で面白い。難易度やテーマに合わせて文体を変えられる | 誤りが混じる。チェックが要る |
| **手作り** | 人が書く | 最高品質 | 毎日は続かない |
| **ハイブリッド** | LLM で下書き → 自動チェック → 必要なら人が直す | 現実的 | 仕組みが少し複雑 |

**提案**: ハイブリッド。ビルド時に LLM でヒントを作り、自動チェックを通す。

### 5.2 ヒントの自動チェック項目

- 答えの文字列（表記・読み）がヒントに含まれていない。
- 1つの答えに絞れる（別の LLM 呼び出しでヒントだけ渡して解かせ、正解するか確かめる）。
- 長さが適当（例: 40文字以内）。
- 不適切な表現がない。
- 失敗したら作り直す。何度やっても失敗する単語は盤面から外して組み直す。

### 5.3 ヒントの種類（遊びの幅）

- 定義型: 「秋に旬を迎える、焼くとおいしい魚」→ サンマ
- 穴埋め型: 「○○も木から落ちる」→ サル
- 連想型: 「ジャック・オー・ランタン」→ カボチャ
- なぞなぞ型（難しい日用）: 「…」

難易度に応じて混ぜる割合を変えられる。

## 6. テーマと応用

| 案 | 内容 |
|---|---|
| 日替わりテーマ | 季節・記念日・年中行事（例: 10月31日はハロウィン） |
| 曜日で難易度 | 月曜が易しく、週末ほど難しい（米国 NYT 方式） |
| 学習用 | 英単語・漢字・歴史用語・資格試験用語 |
| 多言語対戦 | 同じテーマで日本語版・英語版を同時に出す |
| 二重マスのキーワード | 盤面の特定マスから「今日の言葉」が浮かび上がる |
| 地域版 | 地名・名産品・方言 |
| 子ども向け | 小さな盤面、ひらがな表示、絵のヒント |

## 7. 多言語対応の設計

言語ごとに違う部分を「ロケール設定」として1か所にまとめる。

| 項目 | 日本語 | 英語（例） |
|---|---|---|
| マスに入る文字 | カタカナ（ア〜ン、濁音、ー） | A〜Z |
| 文字の正規化 | ひらがな→カタカナ、小書き→大書き | 小文字→大文字、アクセント除去 |
| 入力方式 | 単語単位の入力欄（IME 対策） | マスへの直接入力も可 |
| カギの見出し | タテ / ヨコ | Down / Across |
| 単語リスト | 日本語辞書 | 英語辞書 |
| ヒント生成の指示 | 日本語で作る | 英語で作る |

UI の文言は `i18n/ja.json` のような辞書ファイルに分ける。
パズルの JSON には `"locale": "ja"` を持たせる。

## 8. データの形式

ファイルは2種類だけ。

```
単語リスト (テーマごと: fish.json など)
   │  ① 盤面を組む
   ▼
クロスワード (puzzle.json)   ← clue は null
   │  ② ヒントをつける（同じファイルに書き足す）
   ▼
クロスワード (puzzle.json)   ← clue が埋まった完成品 → HTML に埋め込む
```

ヒントは単語リストではなくクロスワードの側に持たせる。

- ヒントが必要なのは、盤面に入った約20語だけ。
- 同じ単語でも、その日のテーマや難易度に合わせてヒントを変えられる。
- クロスワードのファイル1つで完結するので、HTML にはこのファイルだけを埋め込めばよい。

### 8.1 単語リスト（テーマごとに1ファイル） `data/words/ja/<テーマ>.json`

単語リストはテーマごとに分ける。1テーマ 500〜1000 語を目安にする。

```
data/words/ja/
├── food.json      食べ物
├── fish.json      魚
├── autumn.json    秋
├── general.json   汎用（テーマの単語で埋まらないときの補充用）
└── ...
```

```json
{
  "locale": "ja",
  "theme": "fish",
  "title": "魚",
  "clueStyle": "図鑑風に。姿・生態・旬・料理法・漢字表記などから出題する。",
  "rules": ["一般的な呼び名で答える（地方名・学名は使わない）"],
  "words": [
    { "answer": "サンマ", "display": "秋刀魚", "level": 1 },
    { "answer": "ブリ",   "display": "鰤",     "level": 1 }
  ]
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `theme` | ○ | テーマの ID（ファイル名と同じ。英小文字） |
| `title` | ○ | 画面に出すテーマ名 |
| `clueStyle` | ○ | このテーマのヒントの作り方（②のヒント生成に渡す指示） |
| `rules` | ○ | このテーマの但し書き（画面に表示する。なければ空配列） |
| `words[].answer` | ○ | マスに入る文字列。正規化済みのカタカナ（下記ルール） |
| `words[].display` | ○ | 答えを見せるときに添える表記（漢字など） |
| `words[].level` | | 難易度。1=やさしい 〜 3=むずかしい |
| `words[].note` | | ヒント作りの手がかり（任意。例: 「出世魚」） |

テーマごとに分ける理由:

- テーマごとにヒントの作り方が違う（魚なら図鑑風、秋なら季節の風物詩として、など）。
  `clueStyle` をファイルに持たせ、ヒント生成時にそのまま使う。
- リストを作るとき・直すときに、テーマ単位で作業できる。
- 同じ単語が複数のファイルに入ってよい（サンマは食べ物・魚・秋のどれにも入る）。
  どのファイルから選ばれたかで、ヒントの切り口が変わる。

#### 汎用リスト `general.json`

テーマに関係なく使える一般的な単語（`イヌ`、`ヤマ`、`テガミ` など）を集めたリスト。
形式はテーマファイルと同じで、`theme` は `general`。

- 交差の都合でテーマの単語だけでは埋まらないとき、すき間を埋めるために使う。
- 2〜3文字の短い語を多めに入れておく（交差を作りやすい）。
- `clueStyle` は汎用（辞書の語義を、やさしく言い換える）。

#### 単語を選ぶ優先順位

1. その日のテーマファイルの単語を優先して置く。
2. テーマの単語で置けない位置に限り、汎用リストから補う。
3. 汎用リストから使う語は **1パズルあたり最大2語** にする（設定で変えられる）。
   超える場合は配置をやり直す。

テーマを組み合わせたい日（例: 「秋の味覚」＝秋 × 食べ物）は、複数のテーマファイルを合わせて使う。
どの場合も、各単語がどのファイル由来かを `theme` に記録する。

日本語の `answer` の文字ルール:

- カタカナのみ。濁音・半濁音は清音とは別の1文字（`ガ` ≠ `カ`）。
- 小さい文字は大きい文字にする（`ャ→ヤ`、`ッ→ツ`、`ァ→ア`）。
- 長音「ー」は1文字。
- 「ヴ」は使わない。バ行に置き換える（`ヴァ→バ`、`ヴィ→ビ`、`ヴ→ブ`、`ヴェ→ベ`、`ヴォ→ボ`）。
  小さい文字を大きくする前に置き換える（先に `ァ→ア` をすると `ヴァ→ブア` になってしまうため）。
- 同じ `answer` が複数あってもよい（`ハシ`＝橋・箸など）。`answer` と `display` の組で区別する。

### 8.2 クロスワード `puzzles/YYYY-MM-DD-ja.json`

```json
{
  "id": "2026-10-11-ja",
  "date": "2026-10-11",
  "locale": "ja",
  "theme": "秋の味覚",
  "rules": ["国名は略称で答える"],
  "size": { "rows": 9, "cols": 9 },
  "grid": [
    "サンマ#####",
    "#####..."
  ],
  "words": [
    {
      "number": 1,
      "direction": "across",
      "row": 0,
      "col": 0,
      "answer": "サンマ",
      "display": "秋刀魚",
      "theme": "fish",
      "clue": null
    }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `rules` | 使ったテーマの但し書き（テーマファイルの `rules` を集めたもの） |
| `grid` | 正解の盤面。1行1文字列。`#` は文字の入らないマス |
| `words[].number` | カギ番号（左上から順に振る） |
| `words[].direction` | `across`（ヨコ）または `down`（タテ） |
| `words[].row`, `col` | 単語の先頭マスの位置（0 始まり） |
| `words[].theme` | どのテーマファイルから選ばれたか（ヒントの作り方を決める） |
| `words[].clue` | ヒント。①の時点では `null`、②で書き込む |

`grid` と `words` は同じ情報を重複して持つが、UI で扱いやすいので両方持たせる。
読み込み時に食い違いがないか検証する。

## 11. 決めたいこと

1. 盤面の方式: まず自由配置型（B）から始めてよいか。最終的に日本式（A）を目指すか。
2. 盤面サイズと単語数の目安（例: 9×9、12〜20語）。
3. 単語リストの入手元（JMdict を使うか、テーマごとに LLM で作るか）。
4. ヒント生成に LLM を使うか。使う場合、API キーを GitHub Secrets に置く運用でよいか。
5. テーマの決め方: 自動（季節・記念日から）か、事前にカレンダーを作っておくか。
6. 生成スクリプトの言語: Node.js / Python のどちらにするか。
7. 公開先: GitHub Pages でよいか。

## 12. テーマごとの決めごと

### 国名 `countries.json`

- 略称を使う（外務省の略称に準じる。例: 「アメリカ」「イギリス」「ドイツ」）。
- 但し書き: 「国名は略称で答えてください（例: アメリカ合衆国 → アメリカ）」
- 未定: 国ではない地域（台湾・香港・グリーンランドなど）を含めるか。
