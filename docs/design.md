# xword001 設計ドキュメント

多言語対応のクロスワードパズルを自動生成し、1日1問公開する静的サイト。
最初は日本語版を作る。

- ステータス: たたき台（相談しながら更新する）
- 最終更新: 2026-10-11

---

## 1. 目的と方針

| 項目 | 方針 |
|---|---|
| 形態 | 静的サイト（サーバー処理なし）。1日1回ビルドして公開 |
| 言語 | まず日本語。後から英語などを追加できる構造にしておく |
| 答えの扱い | HTML 内の JavaScript にヒント・答えをそのまま埋め込んでよい（隠さない） |
| 生成 | 盤面の組み立てもヒント作成も自動化する |
| 遊び方 | ヒントを選ぶ → 文字を入力 → マスが埋まる。諦めたら答えを見られる |

答えを隠さないので、暗号化やサーバー側での判定は要らない。そのぶん仕組みを単純にできる。

## 2. 全体構成

```
[単語リスト]          [テーマ設定]
      │                  │
      ▼                  ▼
┌──────────────────────────────┐

└──────────────────────────────┘
      │  配置済み単語の一覧
      ▼
┌──────────────────────────────┐
│ 2. ヒント生成（単語ごとにカギを作る）│
└──────────────────────────────┘
      │  puzzle.json
      ▼
┌──────────────────────────────┐
│ 3. 検証（品質チェック）             │
└──────────────────────────────┘
      │
      ▼
┌──────────────────────────────┐
│ 4. HTML 出力（テンプレート + データ）│
└──────────────────────────────┘
      │
      ▼
 GitHub Actions（毎日 cron）→ GitHub Pages で公開
```

- 生成スクリプトは Node.js（または Python）で書き、GitHub Actions で毎日実行する。
- 出力は `site/YYYY-MM-DD.html` と `site/index.html`（当日分）。過去問も一覧で残す。

## 3. UI 仕様（日本語版）

### 3.1 画面構成

```
┌─────────────────────────────┐
│  2026年10月11日のクロスワード  [テーマ: 秋の味覚] │
├───────────────┬─────────────┤
│               │ タテのカギ     │
│   盤面グリッド   │  1. 秋の…    │
│  （選択中の単語は │  2. …        │
│   ハイライト）    │ ヨコのカギ     │
│               │  1. …        │
├───────────────┴─────────────┤
│ [選択中] タテ1: 秋に旬を迎える… (4文字)│
│ [ 入力欄           ] [入れる]        │
│ [この答えを見る] [全部の答えを見る] [リセット]│
└─────────────────────────────┘
```

### 3.2 操作の流れ

1. カギ一覧の項目、または盤面のマスをタップすると、その単語を選ぶ。
   盤面の該当マスとカギがハイライトされる。
2. 入力欄に答えを入れて確定すると、マスが埋まる。
3. 交差するマスは、後から入れた文字で上書きする（上書きの前に確認は出さない）。
4. 全部のマスが正しく埋まったら「完成！」を表示する。
5. 諦めたときのボタンは2つ:
   - **この答えを見る**: 選択中の単語だけを表示する
   - **全部の答えを見る**: 盤面全体を表示する

### 3.3 日本語入力の扱い（重要）

マスに直接1文字ずつ打つ方式は、スマホの IME（かな漢字変換）と相性が悪い。
そこで「単語ごとに入力欄へ打って確定する」方式を基本にする。

- 入力されたひらがなはカタカナに変換して比較する（どちらで打ってもよい）。
- 小さい文字は大きい文字として扱う（`ャ→ヤ`、`ッ→ツ`、`ァ→ア`）。
- 「ヴ」は使わない。入力された「ヴ」はバ行に置き換える（8.1 の文字ルール）。
  日本のクロスワードで一般的なルール。
- 濁点・半濁点は区別する（`ガ` と `カ` は別の文字）。
- 長音「ー」は1文字として扱う。
- 文字数が足りない・多すぎるときは、入るぶんだけ入れて警告を出す。
- 正誤は入れた時点では出さない（任意で「答え合わせ」ボタンを付ける）。

### 3.4 但し書き（ルールの表示）

パズルの画面に、答えの書き方のルールを必ず表示する。2段に分ける。

| 種類 | 置き場所 | 例 |
|---|---|---|
| 全体のルール（言語ごと） | ロケール設定（`generator/locales/ja`） | 小さい文字は大きい文字で入れる／「ヴ」は使わずバ行で表す／濁点・半濁点は別の文字 |
| テーマのルール | テーマファイルの `rules` | 国名は略称（「アメリカ」「イギリス」）。正式名称ではない |

テーマのルールは、テーマファイルからクロスワードのファイルへ写し、HTML に表示する。
複数のテーマを組み合わせた日は、使ったテーマのルールをすべて表示する。

### 3.5 実装（`template/puzzle.html`）

- テンプレートにクロスワードの JSON と言語設定（`generator/locales/ja.js` のソース）を埋め込み、1枚の HTML にする
  （`generator/site.js`）。文字の正規化は生成側と画面側で同じコードを使う。
- 外部ライブラリなし。`site/YYYY-MM-DD.html` と、最新日付の `site/index.html` を出力する。
- 盤面は SVG で描く。マスの大きさは viewBox の座標で固定し、状態が変わるたびに盤面をまるごと描き直す
  （以前は CSS グリッドの `1fr` で並べていたため、文字が入るたびにマスの大きさが計算し直され、盤面がずれた）。
- 操作:
  - カギ一覧の項目、または盤面のマスを押すと、その単語を選ぶ。同じマスをもう一度押すとタテ・ヨコを切り替える。
  - 入力欄に答えを入れて Enter（または「入れる」）で、マスが埋まる。正しい文字数なら次の空いている単語へ進む。
  - 全部のマスが埋まったら、必ず判定を出す。正しければ「完成！」、まちがいがあれば「間違いがあります（N語）」と出し、
    まちがったマスと、そのマスを含む単語のカギを赤くする（もったいぶらない）。直せばその場で色が消える。
  - 途中で「答え合わせ」を押したときも同じように色をつける。この色は次に答えを入れたときに消える。
  - 「この答えを見る」「全部の答えを見る」で答えを表示する。見た単語には、カギの横に表記（漢字など）を出す。
    自分で入れた文字と違っていたマスは青い文字にする。
  - 答えを見た場合は、正しく埋まっても「完成！」ではなく「全部うまりました」と出す。
  - 途中経過（入力・答えを見たかどうか）は `localStorage` に保存する。
- 動作確認: Playwright（Chromium）で、入力・正規化・答え合わせ・文字数ちがい・答えを見る・タテヨコ切り替え・
  再読み込み後の復元・完成表示・スマホ幅（375px）で横にはみ出さないこと、を確認した。

### 3.6 デザイン（羊皮紙と銅版画）

- 羊皮紙色の背景、こげ茶の文字と線、くすんだ金色の差し色。マスは背景より明るいクリーム色。空きマスは塗らない。
- 文字はすべて明朝（しっぽり明朝）。英字は Cormorant Garamond（Google Fonts）。
- ヘッダー: 英字の「YOROZU CROSSWORD」と、サイト名「よろずのクロスワードパズル」。
- 見出しは中央そろえ。日付 → 「[テーマ]のクロスワードパズル」→ テーマの英語名（副題）→ 罫線で囲んだテーマの説明。
- 検索向け: `<title>` は「[テーマ]のクロスワードパズル｜よろずのクロスワードパズル」、meta description はテーマの説明。
- 開いた直後は、盤面の位置にテーマの正方形の絵を出し、ページを読み終えてから 1.2 秒で消して盤面を見せる
  （タップでもすぐ消える。読み込みが遅くても 4 秒で消す。動きを減らす設定の端末では出さない）。
- 絵は銅版画（エングレービング）風にそろえる。
- テーマごとに変えられるもの（テーマファイル）:

| 項目 | 内容 |
|---|---|
| `subtitle` | テーマの英語名。見出しの下に出す |
| `description` | テーマの説明。見出しの下に罫線で囲んで出す。meta description にも使う |
| `image` | 最初に出す正方形の絵（`data/images/` のファイル名）。パズル専用の絵 `data/images/<パズルのID>.png`（例: `2026-10-12-ja.png`、webp/jpg/svg も可）があればそちらを優先。どちらもなければ方眼紙の絵（`default.svg`） |
| `design` | 色の差し替え。CSS 変数名と値（例: `{"accent": "#2f4f6f"}`） |

- サイト名は `data/site/<locale>.json` の `name`。

### 3.7 その他

- スマホ優先のレイアウト（盤面は画面幅に合わせて縮める）。
- 途中経過は `localStorage` に日付キーで保存し、再読み込みしても消えないようにする。
- 外部ライブラリなしで、1つの HTML ファイルで動くようにする。

## 4. 盤面の組み方（相談事項）

### 4.1 方式の候補

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. 日本式（黒マス型）** | 正方形の盤面を白マスと黒マスで埋める。白マスはすべて何かの単語に属する | 新聞・雑誌でおなじみ。密度が高く、解きごたえがある | 単語が大量に必要で、組むのが難しい |
| **B. 自由配置型（スケルトン）** | 単語どうしを交差させて自由に並べる。空白部分が残る | 組みやすい。テーマの単語だけで作れる | 交差が少ないと簡単になりすぎる |
| **C. 二重マス付き（A or B の拡張）** | 特定のマスの文字を並べ替えると「キーワード」になる | 最後にもう一段の楽しみがある。日本の懸賞パズルの定番 | キーワードの文字が盤面に含まれるよう調整が要る |

### 4.2 日本式（A）のルール

一般的な日本のクロスワードのルール:

- 黒マスはタテ・ヨコに連続しない（斜めは可）。
- 盤面の四隅は黒マスにしない。
- 黒マスで白マスが分断されない（すべての白マスがつながっている）。
- 2文字以上の並びはすべて単語にする（意味のない並びを作らない）。

### 4.3 生成アルゴリズム案

**A（日本式）の場合**

1. 盤面サイズを決める（初めは 7×7〜9×9）。
2. 上のルールを満たす黒マスの配置を作る（ランダム生成して条件で選別する）。
3. 単語の入る枠（スロット）を洗い出す。
4. 制約充足（バックトラック）で単語を埋める:
   - 候補が最も少ないスロットから埋める（MRV ヒューリスティック）。
   - 交差文字が決まったら、他のスロットの候補を絞り込む（前方検査）。
   - 失敗したら戻ってやり直す。一定回数で失敗したら黒マスの配置からやり直す。
5. テーマの単語を優先して入れる（スコアを高くする）。

**B（自由配置）の場合**

1. テーマの単語を長い順に並べる。
2. 1語目を中央に置き、残りを「既存の文字と交差できる位置」に置いていく。
3. 交差数が多い配置を優先する。何通りか試して最も密なものを採用する。

**提案**: まず B で動くものを作り、UI とヒント生成を固める。
その後 A に進む。A のほうが辞書（大量の単語）を必要とするため。

### 4.4 単語リスト

| 候補 | 内容 | 注意点 |
|---|---|---|
| JMdict（EDRDG） | 日英辞書。読みが付いている | CC BY-SA。クレジット表記が要る |
| Wikipedia の記事タイトル | 固有名詞・時事に強い | 読みの取得が別途必要 |
| 自作リスト | テーマごとに手で作る | 量が限られる |
| LLM で生成 | テーマを渡して候補を出させる | 読みや実在性の検証が要る |

日本語のパズルでは「読み（カタカナ）」がマスに入る文字になる。
単語ごとに `表記`・`読み`・`品詞`・`難易度`・`タグ（テーマ）` を持たせる。

## 5. ヒントの作り方（相談事項）

### 5.1 方式の候補

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **辞書の定義を流用** | 辞書の語義文をヒントにする | 正確 | 硬くて面白くない。答えがそのまま書かれていることがある |
| **LLM で生成** | 単語とテーマを渡してヒント文を作らせる | 自然で面白い。難易度やテーマに合わせて文体を変えられる | 誤りが混じる。チェックが要る |
| **手作り** | 人が書く | 最高品質 | 毎日は続かない |
| **ハイブリッド** | LLM で下書き → 自動チェック → 必要なら人が直す | 現実的 | 仕組みが少し複雑 |

**提案**: ハイブリッド。ビルド時に LLM でヒントを作り、自動チェックを通す。

### 5.2 ヒントの自動チェック項目

- 答えの文字列（表記・読み）がヒントに含まれていない。
- 1つの答えに絞れる（別の LLM 呼び出しでヒントだけ渡して解かせ、正解するか確かめる）。
- 長さが適当（例: 40文字以内）。
- 不適切な表現がない。
- 失敗したら作り直す。何度やっても失敗する単語は盤面から外して組み直す。

### 5.3 ヒントの種類（遊びの幅）

- 定義型: 「秋に旬を迎える、焼くとおいしい魚」→ サンマ
- 穴埋め型: 「○○も木から落ちる」→ サル
- 連想型: 「ジャック・オー・ランタン」→ カボチャ
- なぞなぞ型（難しい日用）: 「…」

難易度に応じて混ぜる割合を変えられる。

### 5.4 標準の仕組み（実装済み）

単語ごとに AI に文章を書かせる工程は、カギ（`clue`）と解説（`explanation`）の2つ。どちらも同じ部品・同じ流れで動き、
まだ空の単語だけを埋める（途中で止まっても、もう一度動かせば続きから埋まる）。
テーマごとの違いはテーマファイルの `clue` / `explanation` にだけ書く。

```
テーマごとに単語を分ける
  → 依頼を作る（言語の標準の指示 ＋ テーマの clue ＋ 単語の一覧）  generator/clues/request.js
  → writer に書かせる                                               generator/clues/writers/
  → 自動チェック                                                    generator/clues/checks.js
  → 落ちたものだけ、理由を添えて書き直させる（最大3回）            generator/clues/index.js
```

| 部品 | 内容 |
|---|---|
| 言語の標準の指示 | `generator/locales/ja.js` の `clueDefaults`。常体で短く・答えを含めない・答えが1つに絞れる・確かな事実だけ、など |
| テーマの指示 | テーマファイルの `clue.style` と `clue.examples` |
| 単語の一覧 | 表記・読み・文字数・`note`（ヒント作りの手がかり） |
| writer | 書き手の差し替え口。`openai`（OpenAI API）と `file`（用意したカギを使う）がある |
| 自動チェック | カギ: 空でない／最大文字数以内／答え（読み・表記）を含まない／他の単語と同じカギでない。解説: 空でない／最大文字数以内（答えを見たあとに読むので、答えを含んでよい） |
| 解説の依頼 | 単語の一覧にその単語のカギも添え、カギと同じ内容をくり返さないようにさせる |

- AI は OpenAI を使う。writer は Responses API で、JSON の形を指定して（Structured Outputs, `strict: true`）カギを受け取る。
  モデルは `--model` か環境変数 `OPENAI_MODEL` で指定する（省略時は `gpt-5.5`）。
- 断られた応答（refusal）や、途中で切れた応答（incomplete）はエラーにする。
- 今回の単語が `clue.examples` にも入っているときは、その手本を依頼から外す（手本をそのまま写されるため）。
- `npm run texts` は `NODE_USE_ENV_PROXY=1` を付けて動かす。Node.js 22.21 以上の fetch が `HTTPS_PROXY` を使うようになる
  （Claude Code のクラウド環境ではこれがないと api.openai.com に届かない。プロキシのない環境では影響しない）。
- 動作確認（2026-10-11, gpt-5.5）: 国名テーマ14語を1回の呼び出しで生成し、14語とも自動チェックを通った（約23秒）。
- 答えの漏れは、カギを `normalize()` してから探す。ひらがなや小さい文字で書かれていても見つかる。
- 未実装: 「カギだけを見せて解かせ、正解するか」を確かめるチェック（5.2）。

使い方:

```
npm run texts -- --puzzle puzzles/2026-10-12-ja.json                       # カギ → 解説の順に OpenAI で書く
npm run texts -- --puzzle puzzles/2026-10-12-ja.json --only explanation    # 解説だけ
npm run texts -- --puzzle puzzles/2026-10-12-ja.json --only intro          # 紹介文と画像プロンプトだけ
npm run texts -- --puzzle puzzles/2026-10-12-ja.json --drafts texts.json   # 用意した文章を使う
```

### 5.5 解説（実装済み）

解説は、読む気になっているその瞬間に出す。

- 単語を正しく入れたら、その単語のカギの下に解説を出し、入力欄の下にも「正解！ 〇〇：解説」を出す
  （正解するとカギの選択は次の単語へ移るので、入力した場所の近くでも読めるようにする）。
  1回の入力で交差する単語も同時に正解になった場合は、その単語もカギの下と入力欄の下の両方に出す（入力した単語を先頭に）。
  解説を出すかどうかは毎回マスの状態から決めるので、あとから交差のマスを間違った文字で上書きすると、その単語の解説は消える。
- 「この答えを見る」を押した単語も同じ（入力欄の下には「答え 〇〇：解説」）。
- 完成したとき、または「全部の答えを見る」を押したときは、すべてのカギの下に出す。
- 解説が出るかどうかで、その単語が正解かどうかがわかる。もったいぶらない方針なので、それでよいとする。

- 国名などテーマの語: その国を知るきっかけになる話（位置・言語・名物・歴史など）。
- テーマ外の「つなぎの言葉」（汎用リストから補った語）: 解説の頭に「つなぎの言葉」の印をつけ、本文は軽い豆知識にする。
  謝ったり断ったりはしない（印で伝わるため）。書き方は `general.json` の `explanation.style` で変えられる。
- 解説も AI が書くので、事実の誤りが混じる。2026-10-12 の問題では15語中2語に誤りがあり、手で直した
  （ハワイが「米国で唯一コーヒーを商業栽培」→ 誤り、北マケドニアの旧国名の説明 → 不正確）。
  解説の事実確認の仕組み（別の呼び出しで確かめる、メモにある事実だけを使わせる、など）は今後の課題。

## 6. テーマと応用

| 案 | 内容 |
|---|---|
| 日替わりテーマ | 季節・記念日・年中行事（例: 10月31日はハロウィン） |
| 曜日で難易度 | 月曜が易しく、週末ほど難しい（米国 NYT 方式） |
| 学習用 | 英単語・漢字・歴史用語・資格試験用語 |
| 多言語対戦 | 同じテーマで日本語版・英語版を同時に出す |
| 二重マスのキーワード | 盤面の特定マスから「今日の言葉」が浮かび上がる |
| 地域版 | 地名・名産品・方言 |
| 子ども向け | 小さな盤面、ひらがな表示、絵のヒント |

## 7. 多言語対応の設計

言語ごとに違う部分を「ロケール設定」として1か所にまとめる。

| 項目 | 日本語 | 英語（例） |
|---|---|---|
| マスに入る文字 | カタカナ（ア〜ン、濁音、ー） | A〜Z |
| 文字の正規化 | ひらがな→カタカナ、小書き→大書き | 小文字→大文字、アクセント除去 |
| 入力方式 | 単語単位の入力欄（IME 対策） | マスへの直接入力も可 |
| カギの見出し | タテ / ヨコ | Down / Across |
| 単語リスト | 日本語辞書 | 英語辞書 |
| ヒント生成の指示 | 日本語で作る | 英語で作る |

UI の文言は `i18n/ja.json` のような辞書ファイルに分ける。
パズルの JSON には `"locale": "ja"` を持たせる。

## 8. データの形式

ファイルは2種類だけ。

```
単語リスト (テーマごと: fish.json など)
   │  ① 盤面を組む
   ▼
クロスワード (puzzle.json)   ← clue は null
   │  ② ヒントをつける（同じファイルに書き足す）
   ▼
クロスワード (puzzle.json)   ← clue が埋まった完成品 → HTML に埋め込む
```

ヒントは単語リストではなくクロスワードの側に持たせる。

- ヒントが必要なのは、盤面に入った約20語だけ。
- 同じ単語でも、その日のテーマや難易度に合わせてヒントを変えられる。
- クロスワードのファイル1つで完結するので、HTML にはこのファイルだけを埋め込めばよい。

### 8.1 単語リスト（テーマごとに1ファイル） `data/words/ja/<テーマ>.json`

単語リストはテーマごとに分ける。1テーマ 500〜1000 語を目安にする。

```
data/words/ja/
├── food.json      食べ物
├── fish.json      魚
├── autumn.json    秋
├── general.json   汎用（テーマの単語で埋まらないときの補充用）
└── ...
```

```json
{
  "locale": "ja",
  "theme": "fish",
  "title": "魚",
  "clue": {
    "style": "図鑑風に。姿・生態・旬・料理法・漢字表記などから出題する。",
    "examples": [{ "answer": "サンマ", "display": "秋刀魚", "clue": "秋が旬の細長い銀色の魚" }]
  },
  "rules": ["一般的な呼び名で答える（地方名・学名は使わない）"],
  "words": [
    { "answer": "サンマ", "display": "秋刀魚", "level": 1 },
    { "answer": "ブリ",   "display": "鰤",     "level": 1 }
  ]
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `theme` | ○ | テーマの ID（ファイル名と同じ。英小文字） |
| `title` | ○ | 画面に出すテーマ名 |
| `clue.style` | ○ | このテーマのカギの作り方（②のヒント生成に渡す指示） |
| `clue.examples` | | カギの手本（2〜3個） |
| `clue.maxLength` | | カギの最大文字数（省略時は言語の標準。日本語は40） |
| `explanation.style` | | このテーマの解説の書き方 |
| `explanation.maxLength` | | 解説の最大文字数（省略時は言語の標準。日本語は120） |
| `rules` | ○ | このテーマの但し書き（画面に表示する。なければ空配列） |
| `words[].answer` | ○ | マスに入る文字列。正規化済みのカタカナ（下記ルール） |
| `words[].display` | ○ | 答えを見せるときに添える表記（漢字など） |
| `words[].level` | | 難易度。1=やさしい 〜 3=むずかしい |
| `words[].weight` | | 選ばれやすさ。0〜1、省略時は 1。優先度を下げたい語は小さくする（例: 0.3） |
| `words[].note` | | ヒント作りの手がかり（任意。例: 「出世魚」） |

テーマごとに分ける理由:

- テーマごとにヒントの作り方が違う（魚なら図鑑風、秋なら季節の風物詩として、など）。
  `clue` をファイルに持たせ、ヒント生成時にそのまま使う（5.4 参照）。
- リストを作るとき・直すときに、テーマ単位で作業できる。
- 同じ単語が複数のファイルに入ってよい（サンマは食べ物・魚・秋のどれにも入る）。
  どのファイルから選ばれたかで、ヒントの切り口が変わる。

#### 汎用リスト `general.json`

テーマに関係なく使える一般的な単語（`イヌ`、`ヤマ`、`テガミ` など）を集めたリスト。
形式はテーマファイルと同じで、`theme` は `general`。

- 交差の都合でテーマの単語だけでは埋まらないとき、すき間を埋めるために使う。
- 2〜3文字の短い語を多めに入れておく（交差を作りやすい）。
- カギの作り方は汎用（辞書の意味を、やさしく言い換える）。

#### 単語を選ぶ優先順位

1. その日のテーマファイルの単語を優先して置く。
2. テーマの単語で置けない位置に限り、汎用リストから補う。
3. 汎用リストから使う語は **1パズルあたり最大2語** にする（設定で変えられる）。
   超える場合は配置をやり直す。

テーマを組み合わせたい日（例: 「秋の味覚」＝秋 × 食べ物）は、複数のテーマファイルを合わせて使う。
どの場合も、各単語がどのファイル由来かを `theme` に記録する。

日本語の `answer` の文字ルール:

- カタカナのみ。濁音・半濁音は清音とは別の1文字（`ガ` ≠ `カ`）。
- 小さい文字は大きい文字にする（`ャ→ヤ`、`ッ→ツ`、`ァ→ア`）。
- 長音「ー」は1文字。
- 「ヴ」は使わない。バ行に置き換える（`ヴァ→バ`、`ヴィ→ビ`、`ヴ→ブ`、`ヴェ→ベ`、`ヴォ→ボ`）。
  小さい文字を大きくする前に置き換える（先に `ァ→ア` をすると `ヴァ→ブア` になってしまうため）。
- 中黒「・」や空白は取り除く（`サントメ・プリンシペ→サントメプリンシペ`）。
- 漢字を含む語は、`display` に漢字、`answer` に読みを入れる（`韓国` → `カンコク`）。
- 同じ `answer` が複数あってもよい（`ハシ`＝橋・箸など）。`answer` と `display` の組で区別する。

### 8.2 クロスワード `puzzles/YYYY-MM-DD-ja.json`

```json
{
  "id": "2026-10-11-ja",
  "date": "2026-10-11",
  "locale": "ja",
  "theme": "autumn+food",
  "title": "秋・食べ物",
  "rules": ["国名は略称で答える"],
  "size": { "rows": 9, "cols": 9 },
  "grid": [
    "サンマ#####",
    "#####..."
  ],
  "words": [
    {
      "number": 1,
      "direction": "across",
      "row": 0,
      "col": 0,
      "answer": "サンマ",
      "display": "秋刀魚",
      "theme": "fish",
      "clue": null
    }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `theme` | 使ったテーマファイルの ID（複数なら `+` でつなぐ） |
| `title` | 画面に出すテーマ名 |
| `rules` | 使ったテーマの但し書き（テーマファイルの `rules` を集めたもの） |
| `grid` | 正解の盤面。1行1文字列。`#` は文字の入らないマス |
| `words[].number` | カギ番号（左上から順に振る） |
| `words[].direction` | `across`（ヨコ）または `down`（タテ） |
| `words[].row`, `col` | 単語の先頭マスの位置（0 始まり） |
| `words[].theme` | どのテーマファイルから選ばれたか（ヒントの作り方を決める） |
| `round` | 同じテーマの何回目か。見出しとタイトルに「第N回」と出す。作るときに `puzzles/` の既存分から数える |
| `intro.theme` | テーマ（作るときに指定したもの） |
| `intro.description` | このパズルの紹介文。入った答えを見て AI が書く（答えは書かないよう指示。漏れたら注意を出すだけで止めない）。見出しの下と meta description に使う |
| `intro.imagePrompt` | 表紙の絵を作るための画像プロンプト（英語）。AI が書いた題材に、サイト共通の画風（`data/site/<locale>.json` の `imageStyle`）を付けたもの |
| `words[].explanation` | 解説。完成したとき・全部の答えを見たときに表示する。③で書き込む |
| `words[].clue` | ヒント。①の時点では `null`、②で書き込む |

`grid` と `words` は同じ情報を重複して持つが、UI で扱いやすいので両方持たせる。
読み込み時に食い違いがないか検証する。

## 12. テーマごとの決めごと

### 世界の国と地域 `countries.json`

- 日本が承認している195か国＋日本＝196か国を収録（地域ごとの分類は外務省に準じ、`note` に記入）。
- 略称を使う（外務省の略称に準じる）。ただし「英国」は一般的な「イギリス」とする。
- 但し書き: 「国名は略称で答えてください（例: アメリカ合衆国 → アメリカ）」「国ではない地域（台湾・香港など）も含みます」
- 国ではない地域（台湾・香港・北朝鮮・パレスチナ・グリーンランド・スコットランドなど21件）も入れる。
  優先度を下げるため `weight: 0.3` とし、`note` に位置づけ（「中国の特別行政区」など）を書く。
- 日本の読みは「ニホン」に統一する。
- 10文字以上の語（アラブ首長国連邦など7語）も収録するが、9×9の盤面には入らないので使われない。

### 一般 `general.json`

- テーマの単語で埋まらない位置を補うための汎用リスト（約500語）。
- 交差を作りやすいよう、2〜3文字の語が中心（2文字 235語、3文字 177語）。
- 小学生でもわかる基本的な名詞に限る。`note` に分類（からだ・自然・動物など）を書く。
- 同じ読みの語（ハシ＝橋・箸・端など）は `display` で区別し、ヒントも `display` の意味で作る。
- 但し書き（`rules`）はなし。

## 13. 実装メモ

### 13.1 決まったこと

- 生成スクリプトは JavaScript（Node.js 20 以上、外部ライブラリなし）。
- 将来は AWS Lambda で動かす。そのため、盤面生成（`generator/layout`）と組み立て（`generator/build.js`）は
  ファイル操作をしない関数にし、ファイルの読み書きは `generator/cli` と `generator/lib/words.js` に閉じ込める。
- 乱数は日付・言語・テーマから作る seed で決まる。同じ日付なら同じパズルができる。

### 13.2 使い方

```
npm run make -- --date 2026-10-12 --theme countries   # puzzles/2026-10-12-ja.json を作る
npm run trial -- --theme countries --days 30           # 30日分組んで集計する
npm run texts -- --puzzle puzzles/2026-10-12-ja.json   # カギと解説をつける
npm run site                                           # site/ に HTML を作る
npm test
```

### 13.3 自由配置型の組み方（`freeplace.js`）

1. テーマから4文字以上の語を1つ選び、盤面の中央に置く。
2. 盤面にある文字と交差できる置き方を、テーマの全単語について探す。
   交差数・長さ・`weight` に乱数を掛けた点数が最も高いものを置く。
3. テーマの語で置けないときだけ、汎用リストから探す（最大2語）。
4. 置けなくなるか 20 語に達したら終わり。これを 300 回試し、最も良い盤面を採用する
   （点数 = テーマ語数×10 ＋ 交差マス×3 ＋ 文字のマス×0.5 − 汎用語数×5）。

置くときの条件:

- 単語の前後のマスは空いている。
- 新しく文字を置くマスの両脇（単語と直角の向き）は空いている（意図しない並びを作らない）。
- 交差するマスは同じ文字で、同じ向きの単語がまだ通っていない。

出力後に `validatePuzzle()` で、盤面のすべての並びが単語になっているか・分断がないか・答えの重複がないかを確かめる。

### 13.4 試行結果（国名テーマ 217語＋汎用 496語、9×9、30日分）

| 項目 | 結果 |
|---|---|
| 1問あたりの語数 | 平均 15.9（13〜18） |
| 汎用語の数 | 平均 1.6（0〜2） |
| 交差マス | 平均 16.2（13〜20） |
| 文字の入ったマス | 平均 48.8 / 81 |
| 組めなかった日 | 0 |
| 生成時間 | 1問あたり約 1.8 秒 |

20語には届かないが、国名だけでもほぼテーマの語で埋まる。語数を増やすなら、置き方の探し方を改良するか、盤面を少し大きくする。

### 13.5 API キーの置き場所

キーはリポジトリに置かない。動かす場所ごとに、その場所の秘密情報の保管場所に入れ、環境変数 `OPENAI_API_KEY` として渡す。

| 動かす場所 | 置き場所 |
|---|---|
| Claude Code のクラウド環境 | 環境設定の「Network secrets」。種類は Bearer、許可するサイトは `api.openai.com`、ヘッダーは `Authorization`／接頭辞 `Bearer`。キーはプロキシが付けるので、セッションの中からは見えない |
| GitHub Actions | リポジトリの Secrets（`OPENAI_API_KEY`） |
| AWS Lambda | Secrets Manager か SSM パラメータストア（SecureString） |
| 手元のパソコン | `export OPENAI_API_KEY=...` |

### 13.6 公開（GitHub Pages）

- `.github/workflows/pages.yml`: `main` に入るたびに `site/` を作り直し、GitHub Pages に公開する（手動実行も可）。
- テスト用の URL: `https://okuyamashin.github.io/xword001/`
- 本番では `engawa5656.com` のサブドメインを使う。リポジトリの Settings → Pages の Custom domain に入れ、
  DNS にそのサブドメインの CNAME（向け先 `okuyamashin.github.io`）を追加する。

### 13.7 ページ構成とバックナンバー

| ページ | 内容 |
|---|---|
| `site/<日付>.html` | パズルのページ。下に「同じテーマのほかの回」へのリンク |
| `site/index.html` | いちばん新しいパズル |
| `site/archive.html` | バックナンバー。新着（4問）と、テーマごとの一覧（最近出たテーマから、各テーマは新しい回から）。絵の見本・見出し・第N回・日付・紹介文を出す。この端末で解いたものに「完成」、解きかけに「途中」の印（localStorage の進み具合を読む） |

- どのページにもヘッダーに「最新の問題」「バックナンバー」へのリンク。
- 共通部分は `template/base.css`（色・文字・ヘッダー）、`template/header.html`、`template/footer.html` にまとめ、作るときにはめこむ。

### 13.8 絵の形式と大きさ

- 表紙の絵（PNG・JPEG）は `data/images/<パズルのID>.png` に置き、`npm run images` で WebP に変える。
  - `<ID>.webp`: 800px 四方、品質 72。表紙は 1.2 秒ほどしか出ないので軽さを優先（1040px・品質 78 と見比べて差はほぼなし）。
    例: 2026-10-12 の絵は PNG 4.3MB → WebP 約 200KB
  - `<ID>.thumb.webp`: 176px 四方（一覧の 88px の 2 倍）。品質 72
  - 変換後、元の PNG・JPEG は消す（`--keep` で残す）。リポジトリには WebP だけを入れる。
- 変換には sharp を使う（開発用の依存。公開のワークフローでは使わない）。

### 動物 `animals.json`

- 279語（哺乳類114、鳥68、虫43、海や水辺の生き物26、爬虫類20、両生類8）。魚は別テーマにするため入れない。
- 答えは一般的なカタカナの呼び名。漢字表記（象、鶴など）は `note` に入れ、カギの手がかりにする。
- 但し書き: 「動物の名前は、一般的なカタカナの呼び名で答えてください（例: 象 → ゾウ）」「魚は含みません」
- 試行（30日分）: 毎回 19〜20語、汎用語は平均 0.3語。短い名前が多く、国名より組みやすい。
