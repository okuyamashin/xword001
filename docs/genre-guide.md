# ジャンルの作り方（手引き）

「よろずのクロスワードパズル」に新しいジャンル（テーマ）を足すときの、全手順とルールです。
人が作るときも、Claude Code などの AI が作るときも、この手引きに従います。

- 最終的に作るのは **単語リスト 1 ファイル** と **ジャンルの絵 1 枚** だけです。
- パズル（盤面）は、単語リストから自動で何回でも作れます。AI は使いません。
- OpenAI の API キーが必要なのは **絵を作るとき（手順 4）だけ** です。
  ヒントと解説は、作る人（または Claude Code）が単語リストに直接書けます。

---

## 0. 全体の流れ

```
1. ジャンルを決める（英名・範囲・語数）
2. 単語リストを書く          data/words/ja/<ジャンル>.json
3. カギと解説を書く          同じファイルの各語の clue / explanation
4. 絵を作る                  npm run theme-image -- --theme <ジャンル>    ← OpenAI の API キーが必要
5. 点検する                  npm run check-theme -- --theme <ジャンル> --strict
                            npm run trial -- --theme <ジャンル> --days 20
                            npm test
6. パズルを作る              npm run make -- --theme <ジャンル>
7. ページを作る              npm run site
8. コミットして公開          main に入れる → GitHub Actions が GitHub Pages に公開
```

---

## 1. ジャンルを決める

### 1.1 ジャンルの英名（ジャンル ID）

- **小文字の英字と数字だけ。単語の区切りはアンダースコア `_`。**（例: `animals`、`japanese_history`、`sangetsuki`）
- ファイル名、パズルの ID、絵のファイル名にそのまま使います。あとから変えるのは大変なので、最初に決めます。
- 作品名など英語にしにくいものは、ローマ字でかまいません（例: 山月記 → `sangetsuki`）。

### 1.2 範囲と語数

| 項目 | 目安 |
|---|---|
| 語数 | **80〜300 語**。60 語未満だと盤面が組みにくい（点検で注意が出る） |
| 長さ | 答え（カタカナ）が **2〜9 文字** の語が使われる。10 文字以上も書いてよいが、9×9 の盤面には入らない |
| 範囲 | 「何を入れて、何を入れないか」を先に決め、但し書き（`rules`）に書く（例: 動物 → 魚は入れない） |

組みやすさは、手順 5 の `npm run trial` で確かめます。1 問あたり 15〜20 語入り、つなぎの言葉（汎用リストからの補充）が 0〜2 語なら十分です。

## 2. 単語リストを書く

ファイル: `data/words/ja/<ジャンル>.json`（文字コードは UTF-8）

### 2.1 ファイルの形

```json
{
  "locale": "ja",
  "theme": "sangetsuki",
  "title": "山月記",
  "subtitle": "Sangetsuki — The Moon over the Mountain",
  "description": "中島敦の名作「山月記」。詩人として名を残そうとして、虎になってしまった李徴の物語から、人物・地名・印象的な言葉を集めました。",
  "image": "sangetsuki.webp",
  "imagePrompt": "A tiger standing ... （題材）... Square 1:1 composition. Antique copperplate engraving style ...（サイト共通の画風）",
  "design": { "accent": "#3d4a63" },
  "clue": {
    "style": "作中の場面・人物の言葉・語の意味などから出題する。根拠はメモに書かれた内容に限る。",
    "examples": [{ "answer": "ケンカイ", "display": "狷介", "clue": "李徴の性格。かたくなで人と打ち解けないこと" }]
  },
  "explanation": { "style": "その語が作中のどの場面で、どんな意味で使われているかを、高校の国語の授業で役立つように書く。" },
  "rules": ["作中の言葉は、読みをカタカナで答えてください（例: 李徴 → リチョウ）"],
  "words": [
    {"answer": "リチヨウ", "display": "李徴", "level": 1, "note": "人物。主人公。…", "clue": "発狂して虎となった本作の主人公", "explanation": "冒頭で「隴西の李徴は博学才穎」と紹介されます。…"}
  ]
}
```

- `words` は **1 語 1 行** で書きます（差分が読みやすいように）。プログラムで保存するときもこの形になります。
- 区切りは `"key": value, ` のように、コロンとカンマのあとに空白を 1 つ入れます。

### 2.2 テーマ全体の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `locale` | ○ | `"ja"` |
| `theme` | ○ | ジャンルの英名（1.1）。ファイル名と同じ |
| `title` | ○ | ジャンルの日本語名。ページの見出しは「〈title〉のクロスワードパズル 第N回」になる。**検索に使われる言葉にする** |
| `subtitle` | ○ | 英語の副題。見出しの下に大文字で出る |
| `description` | ○ | ジャンルの説明。2 文程度。ページの見出しの下と、検索結果の説明文（meta description）に使う |
| `image` | ○ | 絵のファイル名。`<ジャンル>.webp` |
| `imagePrompt` | ○ | 絵を作るためのプロンプト（3 章） |
| `design` | | 色の差し替え。`{"accent": "#rrggbb"}`（見出しの印・「第N回」などの色）。羊皮紙色の背景で読める、くすんだ濃い色にする |
| `clue.style` | ○ | このジャンルのカギの書き方（2.6） |
| `clue.examples` | | カギの手本 2 つ程度（`answer`・`display`・`clue`） |
| `clue.maxLength` | | カギの最大文字数（省略時 40） |
| `explanation.style` | ○ | このジャンルの解説の書き方（2.7） |
| `explanation.maxLength` | | 解説の最大文字数（省略時 120） |
| `rules` | ○ | 但し書き（答えの書き方の約束）。ページの「答えの書き方」に出る。なければ `[]` |

### 2.3 単語の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `answer` | ○ | マスに入る文字。文字のルール（2.4）どおりのカタカナ |
| `display` | ○ | 表記。漢字の語は漢字（例: `李徴`）、カタカナの語はカタカナ（例: `キリン`） |
| `level` | | 難しさ。1 = だれでも知っている、2 = ふつう、3 = 難しい |
| `weight` | | 選ばれやすさ（0〜1、省略時 1）。入れておきたいが優先度の低い語は 0.3 など |
| `note` | 強く推奨 | カギと解説の**根拠**。分類、漢字表記、作中の場面、確かな事実を書く。カギと解説はこの内容だけを根拠にする |
| `clue` | 公開時は必須 | カギ（2.6） |
| `explanation` | 公開時は必須 | 解説（2.7） |

- 同じ `answer` で `display` の違う語（`ハシ` ＝ 橋・箸）は入れてよい。同じ `answer` と `display` の組は 1 つだけ。
- ほかのジャンルと同じ語があってもよい（サンマは食べ物にも魚にも入る）。カギや解説はジャンルごとに書く。

### 2.4 文字のルール（answer）

| ルール | 例 |
|---|---|
| カタカナだけ。ひらがなはカタカナに | さだめ → `サダメ` |
| 小さい文字は大きい文字に | シャツ → `シヤツ`、キッテ → `キツテ` |
| 濁点・半濁点のついた文字はそのまま 1 文字 | ガ、パ |
| 長音「ー」は 1 文字 | `キーウィ` → `キーウイ` |
| 「ヴ」は使わず、バ行に（小さい文字を大きくする前に置き換える） | ヴァ → バ、ヴィ → ビ、ヴ → ブ、ヴェ → ベ、ヴォ → ボ |
| 中黒「・」と空白は取る | サントメ・プリンシペ → `サントメプリンシペ` |
| 漢字の語は読みを入れる | 李徴 → `リチヨウ`、北朝鮮 → `キタチヨウセン` |

迷ったら `generator/locales/ja.js` の `normalize()` が正です。点検（手順 5）で、ルールに合わない answer はエラーになります。

### 2.5 単語の選び方

- **だれかが聞いたことのある語**を中心にする。難しい語は `level: 3` にする。
- 読みが何通りもある語は避けるか、但し書きで決める（例: 日本 → ニホン に統一）。
- 呼び方が何通りもある語は、但し書きで決める（例: 国名は略称、動物は一般的なカタカナの呼び名）。
- 作品のジャンル（山月記など）は、作中の言葉を本文どおりに。**本文にない言葉を作中の言葉として入れない**。
  記憶があいまいな語や引用は、入れないか、`note` に引用を書かない。

### 2.6 カギ（clue）の書き方

| ルール | |
|---|---|
| 長さ | **40 文字以内**、短い 1〜2 文 |
| 文体 | 常体か体言止め（「〜の国」「〜するもの」）。です・ます調にしない |
| 答えを書かない | 答えの読み・表記・その一部を入れない（ひらがなで書いても点検で見つかる） |
| 1 つに絞れる | カギだけを読んで答えが 1 つに決まるようにする |
| 事実だけ | 確かなことだけを書く。`note` にないことは書かない |
| 切り口を散らす | 同じ型ばかりにしない（国名なら首都ばかりにしない） |
| 重複しない | 同じジャンルの中で同じカギを使わない |

ジャンルごとの方針は `clue.style` に書きます。カギの例（山月記）:

- 狷介 → 「李徴の性格。かたくなで人と打ち解けないこと」
- 露 → 「「山も樹も月も…も」の伏せた語」

### 2.7 解説（explanation）の書き方

解説は、その単語が正解したとき・答えを見たとき・完成したときに、カギの下に出ます。答えを書いてかまいません。

| ルール | |
|---|---|
| 長さ | **120 文字以内**、2〜3 文 |
| 文体 | です・ます調 |
| 中身 | 「へえ」と思える豆知識を 1 つ入れる。カギと同じことをくり返さない |
| 事実だけ | 確かなことだけ。`note` にないことは書かない。自信がなければ書かない |
| 内部の言葉を出さない | 「メモによると」「note では」のような、作る側の言葉を書かない |

ジャンルごとの方針は `explanation.style` に書きます。

### 2.8 カギと解説を書く方法

どちらの方法でもかまいません。最後に必ず人（または Claude Code）が全部を読みます。

| 方法 | API キー | 手順 |
|---|---|---|
| **直接書く**（Claude Code を含む） | 不要 | 各語の `clue` と `explanation` を JSON に書く。2.6・2.7 のルールに従う |
| OpenAI に書かせる | 必要 | `npm run theme-texts -- --theme <ジャンル>`。`clue.style`・`explanation.style`・`note` をもとに、空の語だけを 25 語ずつ埋める。1 回ごとに保存するので、止まっても続きから |

AI が書いたものには誤りが混じります（例: 山月記では 80 語中 7 語を直した）。とくに次を読み直します。

- 年号・数字・固有名詞
- 作品のジャンルの引用と場面（本文と合っているか）
- 「〜で唯一」「世界最大」などの言い切り

## 3. 絵（ジャンルにつき 1 枚）

### 3.1 プロンプト（imagePrompt）

**題材（英語 1〜2 文）＋ サイト共通の画風（固定の文）** にします。画風の文は `data/site/ja.json` の `imageStyle` をそのまま最後に付けます。

```
（題材）A tiger standing on a grassy clearing at the edge of a misty forest, raising its head toward a pale setting moon at dawn, while a small party of travelers on horseback looks back from a distant hill; mountains of ancient China, dew on the grass.
（画風）Square 1:1 composition. Antique copperplate engraving style with fine line work and cross-hatching, sepia ink on aged parchment paper, muted warm tones, 19th-century book illustration. No text, no letters, no numbers, no labels, no border.
```

- 題材は、そのジャンルを 1 枚で表す情景にする（動物 → 図鑑の 1 ページのように動物が集まった絵）。
- 文字・ラベル・地図上の国名は描かせない（画風の文に含まれている）。
- 範囲外のものを入れない（動物なら「No fish.」）。

### 3.2 作り方

```
npm run theme-image -- --theme <ジャンル>            # 作る（すでにあれば何もしない）
npm run theme-image -- --theme <ジャンル> --force    # 作り直す
```

- OpenAI の画像生成（`gpt-image-2`、1024px）で作り、受け取った PNG をそのまま WebP に変えます。PNG はリポジトリに入れません（GitHub に大きなファイルを入れないため）。
  - `data/images/<ジャンル>.webp`（800px、約 200KB）… 表紙
  - `data/images/<ジャンル>.thumb.webp`（176px、約 10KB）… バックナンバーの一覧
- テーマファイルの `image` に名前を書き込みます。
- **API キーが必要です。** Claude Code のクラウド環境では、環境設定の Network secrets に `api.openai.com` 用のキー（Bearer）を登録しておきます。
- 手で用意した絵を使うときは `data/images/<ジャンル>.png` に置いて `npm run images`（WebP に変えて PNG を消す）。
- 絵ができるまでは、方眼紙の絵が代わりに出ます。

## 4. 点検する

```
npm run check-theme -- --theme <ジャンル> --strict   # 公開してよい状態か（エラーが 0 になるまで直す）
npm run trial -- --theme <ジャンル> --days 20        # 盤面がどのくらい組めるか
npm test                                            # 全体のテスト
```

`check-theme` が確かめること:

- 必須の項目がそろっているか、ジャンルの英名とファイル名が命名ルールどおりか
- answer が文字のルールどおりか、長さ、重複
- カギ: 空でない・40 文字以内・答えを含まない・同じジャンルで重複しない
- 解説: 空でない・120 文字以内
- 絵のファイルがあるか、imagePrompt の最後がサイト共通の画風か
- `--strict` のとき: すべての語にカギと解説があるか

答えの漏れの点検は、短い答えで誤検知することがあります（例: 答え「カリ」と「手がかり」）。カギを言い換えて直します。

## 5. パズルを作り、公開する

```
npm run make -- --theme <ジャンル>     # puzzles/<ID>.json を作る（AI は使わない）
npm run site                          # site/ にページを作る
```

- パズルの ID は **`<全体の通し番号5桁>-<ジャンル>-<ジャンル内の連番3桁>`**（例: `00004-sangetsuki-002`）。番号は自動で決まります。
- 盤面は 9×9 の自由配置。カギと解説は単語リストから書き写します。
  つなぎの言葉（汎用リスト `general.json` の語）にカギと解説がないときは、その語だけ空になるので、
  `general.json` にも書いておくか、`npm run texts -- --puzzle puzzles/<ID>.json` で埋めます。
- 同じジャンルを何回作ってもかまいません（毎回違う盤面になる）。
- `npm run site` は、ジャンルの**単語帳のページ**（`site/words-<ジャンル>.html`）も自動で作ります。
  単語リストの表記・読み・難しさ・カギ・解説がそのまま公開されるので、**公開してよい内容だけを書きます**。
  作る側のメモ（`note`）は単語帳にもダウンロード用の JSON にも出ません。

公開:

1. 変更をコミットして、作業ブランチにプッシュする
2. `main` に入れる（入れるのは持ち主が確認してから）
3. `main` に入ると GitHub Actions（`.github/workflows/pages.yml`）が `site/` を作り直して GitHub Pages に公開する

## 6. チェックリスト

- [ ] ジャンルの英名は小文字・数字・アンダースコアだけ。ファイル名と `theme` が同じ
- [ ] `title`・`subtitle`・`description`・`rules`・`design.accent` を書いた
- [ ] 範囲（入れるもの・入れないもの）を決め、但し書きに書いた
- [ ] 80〜300 語。answer は文字のルールどおり。`note` に根拠を書いた
- [ ] すべての語にカギと解説がある（2.6・2.7 のルールどおり）
- [ ] カギと解説を全部読み、事実・引用・言い回しを確かめた
- [ ] `imagePrompt` は「題材＋サイト共通の画風」。絵を作り、見て確かめた
- [ ] `npm run check-theme -- --theme <ジャンル> --strict` のエラーが 0
- [ ] `npm run trial` で 1 問 15〜20 語入る
- [ ] `npm test` が通る
- [ ] パズルを作り、ページをブラウザ（スマホの幅も）で開いて確かめた
